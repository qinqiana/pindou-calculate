# T28 本地非 OCR 计数实验报告

日期：2026-09-16。范围：已知点阵 + 每色代表格时，能否在不读字、不联网、不装 OpenCV 的条件下逐色计数；并在补充样例上试自动点阵/色号。不是 Android 功能，不写入生产账本。

脚本：[`count_grid.py`](count_grid.py)（Pillow + 标准库，继承 [`grid_probe.py`](../../docs/plans/android-v1-tickets/grid_probe.py)）。148 结果：[`t28-148.json`](t28-148.json)。

## 结论

**已知 29×16 点阵且每色给定一格代表色号时，本地填色采样可以在清晰 148 颗 PNG 上得到与参考答案逐色一致的结果。** 空白 316 + 制作 148 + 未知 0 = 464，未知格没有被改写成空白或零。算法没有读格内文字，也没有读底部图例数量。

**自动点阵和自动色号在本批补充样例上不成立，不能称为已定位或已识号。** 18 张补充图中 15 张自动点阵失败；3 张只得到低置信、未校准的格子猜测，且只能输出未命名色簇。白色空格与 H2、近似色、水印、压缩和过密格子都会破坏逐色相等。色卡不是图纸本体。

因此：本实验可以给后续正式计数票提供「点阵已明确 + 用户确认少量代表格」的辅助路径证据；**不能作为 T38/T41 的全自动识别实现**，也不得把未命名色簇或图例数字冒充算法答案。失败不阻塞 T27。

## 148 颗样例（人工点阵 + 每色代表格）

输入：`参考样例/豆画-Mard-148图纸样例.png`（5000×3820）。

人工披露、并写入 JSON 的输入（算法未从像素读字）：

| 项目 | 值 |
| --- | --- |
| 网格 | 29 列 × 16 行 |
| x0, y0, step | 161, 315, `image.width/31` ≈ 161.2903 |
| 每色代表格 | H7=(2,26), C29=(5,22), C2=(8,14), H2=(5,23), C17=(10,8), C16=(5,17), C19=(9,10), H3=(3,26), C12=(4,24) |
| 棋盘空白样本格 | (1,1), (1,3) |

方法：每格 5×5 样点取众数 RGB；与代表色精确匹配则计入该色号；与空白样本通道差 ≤2 记空白；其余保留未知。

| 色号 | 计数 | 参考答案 |
| --- | ---: | ---: |
| C2 | 18 | 18 |
| C12 | 3 | 3 |
| C16 | 11 | 11 |
| C17 | 12 | 12 |
| C19 | 7 | 7 |
| C29 | 18 | 18 |
| H2 | 14 | 14 |
| H3 | 5 | 5 |
| H7 | 60 | 60 |
| 合计 | 148 | 148 |

格数守恒：148 + 316 + 0 = 16×29。断言通过。

对同一张 148 图另做自动点阵探测（**不用于上述计数**）：失败，原因是标题/图例打断周期峰。官方 148 结果仍只使用人工点阵。

## 步骤边界

| 步骤 | 本实验 | 后续正式计数票 |
| --- | --- | --- |
| 格内填色采样并分类 | 148 清晰 PNG、人工点阵下可用 | 可作候选，需压缩/小格/字迹策略 |
| 棋盘空白 vs 白色制作格 | 148 上靠空白样本格分开 H2 | 白空格图纸上失败，必须单独处理 |
| 自动点阵 | 本批不可靠，失败是有效结果 | 需要人工点阵/校准，或另验定位 |
| 色号 | 必须人工代表格；不读格字、不读图例 | 用户确认映射，或另验 OCR/图例提取（T38） |
| 未知格 | 保持未知 | 不得改空白或零 |

## 能否进入后续正式计数票

- **可以进入的**：把「已知点阵 + 少量代表格 → 本地逐色计数」记为 T41 的一条候选辅助流程，前提是用户（或上游）已经提供点阵和色号映射，并继续把未知格标成疑点。
- **不能进入的**：全自动点阵、全自动识号、把屏幕色或未命名簇写成 MARD 用量、用图例数字反填算法。T38 的 148 图例验收、T41 的多张逐格人工真值，都不被本实验替代。
- **不阻塞**：T27 安卓交付。
