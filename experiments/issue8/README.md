# 只传图纸的本地自动识别基线

版本：`pixel-glyph-0.1`。对应 [Issue #8](https://github.com/qinqiana/pindou-calculate/issues/8)，实施与后续接入见[计划](../../docs/plans/issue8-automatic-recognition.md)。

输入只有图纸文件；不接收手工框、点阵尺寸、色号映射或参考答案。输出是待核对候选，不写账本。`recognize.py` 不读取 `samples.json` 或测试答案，不按文件名切换规则。

## 实现与边界

- 以图形边缘自动寻找图例色条；提取文字形状，和 480 个通用字形模板比较，读出原始色号及数量。原图不发往网络，不调用 OCR 引擎或神经网络模型。
- 自动找规则网格，逐个核对四侧行列编号，逐格识字计数；数字边框不计入制作。颜色不决定 MARD 色号，不合并近似色。
- 文字读取与空白纹理检查分别避开格线/阴影。只有均匀底色或符合棋盘纹理的格子可判空白；低对比文字、透明但缺少其他证据及不可读内容保持未知。
- 可靠图例与完整本体计数逐色一致时返回 `ready`；无图例但独立完整本体成立时也可返回 `ready`。存在冲突、漏项或未证明覆盖时返回 `partial`；无可用候选为 `failed`，总数为 `null`，不是零。
- 不同位置的重复色号保留证据并排除候选；负数、小数、色卡外项目不作为用量。字符有替代解释时保留形状误差与候选间距，不将其称为正确概率。

**当前支持上限：** 同条括号数量图例，以及带四边正向连续数字编号的清晰方格。本体最多 4096 格；其他网格、不同图例排版、细小字、倾斜、水印等可能失败或只返回部分结果。没有承诺任意截图都准确。本体完整核对条件刻意严格，不能把“识别到了几项”写成整图完整。

字形来自系统已有的 Liberation、DejaVu、Noto、Ubuntu 字体，而非图纸裁字。`glyphs.json` 为 190442 字节，运行不需要原字体文件；生成方法在 `generate_glyphs.py`，许可在 `font-notices.txt`。这是字符模板匹配，仍属于读取文字；没有将它包装成“完全不读文字”。

## 复现

依赖已存在的 Python 图像环境：Pillow、NumPy、OpenCV。**本机实验借用这些库，不代表把 Python/OpenCV 随 Android App 打包。** 当前没有安装任何依赖。Android 阶段须适配平台像素输入、移植/选择图像操作并实测包体、峰值内存和速度，本次不声称已经接入。

```bash

/home/kenbattle/apps/comfyui/comfyui-env/bin/python experiments/issue8/benchmark.py --output-dir /tmp/pindou-issue8/frozen-v01
```

`--output` 和 `--output-dir` 只决定诊断结果位置，不是识别输入参数。其他设备使用具备上述库的 Python；不要为了复现修改其他应用的环境。重新生成模板另需生成脚本列出的已有字体；本版本运行只读取已提交模板。

结果字段：`image` 为已纠正方向的原图像素坐标；`candidates` 含色号、数量及证据引用；`evidence` 含原始文字、区域、逐字符误差和替代字；`grid` 含逐格原文、未知格、完整边界与独立计数；`doubts` 记录冲突和拒绝原因；`manualInput` 始终为假。未核实品牌时保留 `brandVerification=not-verified`。未读取标题总数时为 `null`。

## 参数冻结与验收规则

2026-09-20 在开发样例及 7 项边界检查通过后冻结 0.1 版，再运行全部原分组。核心参数：20×28 字形；4 bit 模板覆盖率；灰度/底色对比 65；形状误差上限 0.36、候选间距下限 0.04；比例差权重 0.18、孔洞差权重 0.15；定位预览最长边 2000；方格横纵间距对数差不超过 0.08；空白棋盘主纹理能量不少于 95%。其他固定几何常量完整保留在本版本源码，不对单图动态输入或人工调整。

`samples.json` 已在本任务前期调参前建立，包含 18 张图纸和 1 张色卡，7 个开发样例、12 个验收样例（其中 1 张为色卡）。前期旧网格探针已经运行过验收组；这里不把它宣称为从未见过的盲测集合。本版参数不根据验收组结果回调。变体继承原图的开发/验收分组。

当前只有 148 原图有逐色参考答案；其他图的逐项答案保持未知。`referenceMatch` 仅表示与已有逐色答案比较，完整成功还必须同时为 `ready`。本体隐藏图例测试为开发原图的派生输入，不替代真正无图例图纸验收。

七项检查覆盖：原始九色及独立格数；隐藏标题/图例；截断末行；同名图片改数后不套旧答案；空白输入；坏图与动画；负数、小数、色卡外项、重复项。结果及实测环境见[本次记录](results.json)。每张基准图单独启动进程，峰值 RSS 包含 Python、图像库、原图解码和识别；不是算法权重大小或 Android 内存指标。

本轮自行复核，未做独立 QA。这里交付本地算法验证，不是 Android 真机或用户体验验收。

## 本次实测结果

18 张原图中：S18（148 原图）为 `ready`，九色逐项正确；S03（超密且图例截断）为 `partial`，其 2 项候选没有人工逐项真值，不宣称正确；其余 16 张为 `failed`。额外的色卡 S00 为 `failed`，没有制作数量。失败图仍保留在报告中，这不是 18 图通用识别已通过。

S18 的两条自动路径均为 C2=18、C12=3、C16=11、C17=12、C19=7、C29=18、H2=14、H3=5、H7=60；148 制作格、316 空白格、0 未知格。隐藏标题及图例的派生输入也通过完整逐格计数；这只证明该开发原图的本体路径。

最终单次 S18 运行 1.272 秒，进程峰值 RSS 424513536 字节（约 404.8 MiB），字形文件约 186 KiB。环境为 Python 3.12.3、Pillow 12.3.0、NumPy 2.5.2、OpenCV 5.0.0，Linux aarch64，Cortex-X925/Cortex-A725；不是 Android App 性能。7 项自动检查通过。冻结后仅减少解码拷贝，将初次同图约 496.9 MiB 的峰值降到上述数值；19 个输入的状态和候选数量复验完全一致，未根据验收组调参。

**仍有实质限制：** 大原图的实验进程内存尚不适合直接作为轻量 App 的实现交付，且 17 张其他图纸未完整通过。下一阶段须先扩展受支持版式、减少图像工作缓冲区并完成 Android 原生解码/计算验证，再集成用户选图体验。不能仅凭 190 KB 字形资源承诺应用包体或内存占用。
