## 一、总体判断（先说结论）

**方案大体是对的，而且方向判断相当准。** 具体说三件事：

1. **赛道选对了**：SPEC 把豆计定义为「库存账本 + 图纸消耗闭环」，明确不做照片转网格、图纸编辑、社区、电商——恰好绕开了同质化最严重的红海（国内 10+ 款图纸生成 App、海外一堆免费网页工具），落进了 2026 年才刚有人进入的「库存/用量管理」蓝海分层。
2. **闭环设计比两个直接竞品更严谨**：AI豆仓、拼豆大王都做了「入库→图纸算量→出库扣减」，但都没有撤回、没有估算标记、没有防重复扣减。SPEC 的「已拼/再拼一次/撤回/幂等/快照」是这一赛道目前没人做细的部分。
3. **发现 1 个实质功能缺口 + 1 个需要用户拍板的成本取舍**（见第四、六章）：竞品已验证的「可拼状态筛选」SPEC 里没有；「在线识别作为发布阻塞项」对自用首版是最重的成本中心，值得重新权衡顺序。

评分式结论：方向 ✅ 正确 / 规则颗粒度 ✅ 领先竞品 / 功能完整性 ⚠️ 差一个筛选 / 工程顺序 ⚠️ 识别成本需权衡。

## 二、SPEC 关键决策逐条校验

| SPEC 决策 | 竞品证据 | 校验结论 |
|---|---|---|
| 不做图纸生成，只做库存账本闭环 | 图纸生成赛道 10+ 国内 App + 8+ 海外免费网页工具，功能完全同质；横评显示用户在免费/隐私/导出限制间反复横跳，无忠诚度 | ✅ 正确。红海不进入 |
| 闭环：库存→用量确认→缺口→已拼扣减→撤回 | AI豆仓核心流程即「补豆入库→消耗计算→记录出库→出入库记录」；拼豆大王同构 | ✅ 与已被验证的最小闭环一致 |
| 离线优先、无账号、本地账本、手工完整备份 | AI豆仓：云端同步需登录，**访客模式有丢数据风险，密码不支持自助找回**；拼豆大王：无限云存储是会员权益 | ✅ 直接命中对手软肋，是差异化主武器 |
| 估算/精确逐色标记、百分比低库存预警（基准不随扣减重置）、预填 1000 颗 | 两款直接竞品均无精度标记；Excel 库存表靠手工维护，无预警 | ✅ 颗粒度领先，Excel 党迁移理由 |
| 识别结果只是「候选」，必须用户逐色确认后才入账 | 拼豆大王宣传「AI 识别准确率 99%+」直接自动算豆；smzdm 横评显示 AI 识别/去噪在用户间口碑分化明显 | ✅ 「候选+确认」更诚实，保护账本正确性——这是账本类产品的立身之本 |
| 隐私合同：只传当前截图、处理后删除、服务端不留存 | 云端处理类工具被横评点名「个人照片敏感需谨慎」；本地上传是用户选工具的第一道筛 | ✅ 差异化卖点，建议写进产品文案 |
| 已用成就三指标（累计已用/逐色已用/完成数），口径=未撤回制作快照 | 民间 Excel 表的「高频使用色统计」在社交媒体被自发传播，证明「我想知道用了多少」是真实痛点 | ✅ 痛点命中且统计口径比 Excel 严谨 |
| 零用量图纸也允许已拼、防连点重复扣减 | 竞品未见任何防重/幂等设计描述 | ✅ 领先，正确性壁垒 |
| 撤回任意一条制作记录（快照恢复、不回滚全局） | 两款直接竞品均无撤回能力描述 | ✅ 竞品空白点 |
| 分享模板（朋友圈 + 小红书 9:15 = 1080×1800） | 目标客群=小红书活跃拼豆爱好者（SPEC 用户指定）；拼豆大王作品集证明「晒作品」动机存在 | ✅ 合理，但保持阶段 4 顺序，别提前 |
| 备份恢复=差异预览+整体替换，不合并 | AI豆仓仅提供「导出库存数据」，恢复语义未见 | ✅ 更严谨 |
| 不做外链抓小红书图纸 | 拼豆大王支持「一键提取小红书/抖音高清图片」——有版权/合规风险 | ✅ 排除正确，合规护城河 |
| 不做多豆仓/批次 | AI豆仓有多豆仓（适配收纳习惯） | ✅ 首版排除合理（非目标用户），但记下这是对方已占的差异点 |
| uni-app + Vue3 + TS，Android SQLite 事务，后续迁微信小程序 | PindouAI 用 Flutter；uni-app 对「Android + 微信小程序」双目标路径最直接 | ✅ 合理。风险点（HTML5+ SQLite 老旧、微信端无等价事务）SPEC 已自行识别 |

## 三、直接竞品逐项拆解（切痛点视角）

### 3.1 AI豆仓 —— 流程最全的「重工作台」

| 维度 | 内容 |
|---|---|
| 版本/平台 | v1.5.4（2026-08），Android 为主，多端登录（疑 Web 套壳） |
| 核心流程 | 补豆入库（批量/套装色）→ 图纸册（AI 统计/手动/导入）→ **消耗计算**（显示"不足"色号）→ **记录出库**（自动扣库存）→ 出入库记录 + 消耗统计 |
| 独有功能 | 多豆仓分类、图纸状态（待拼）、付费图纸市集、库存导出备份、深色模式 |
| 商业化 | 会员制（淘宝有"AI豆仓会员 VIP 天卡/年卡"代售，确认存在付费墙）+ 付费图纸市集 |
| 弱点 | ① 五步流程偏重，不是"随手记"；② 访客模式丢数据风险；③ 密码不能自助找回——产品打磨粗糙；④ 数据在云端，隐私让渡 |
| 来源 | https://www.jb51.net/softs/1032313.html , https://www.taobao.com/list/product/wap/ai%E6%95%88%E7%8E%87.htm |

### 3.2 拼豆大王 Beadmaster —— 体验最顺的「智能助手」

| 维度 | 内容 |
|---|---|
| 版本/平台 | v1.2.7（2026-07），Android/iOS/Web 多端同步 |
| 核心流程 | 导入图纸（**可一键提取小红书/抖音图片**）→ AI 识别色号数量（宣称 99%+）→ 实时对比库存显示**「可拼状态」**→ 补货清单一键复制导出 → 完成后自动扣消耗并**智能推荐补货数量** |
| 独有功能 | **图纸状态标签：全部/可拼/可换/拿起/待制作/已完成**；色号高亮辅助拼制；大图自动拆板+逐板进度；作品集（画廊/日历/标签）；库存不足时**自动推荐替代色**（第三方站信息，未验证） |

| 来源 | http://www.jb51.net/softs/1035775.html , https://www.aiskycn.com/az/1305945.html（后者为下载站内容，可信度低，仅作线索） |

库存管控 + 缺豆提醒 + 采购清单 + iPad 蒙板拼豆 + 进度跟踪；个人开发者，2026-03 上架。证明了"单人开发者也能把这个细分做起来"。来源：https://mwm.ai/pt/apps/app/6759092510

## 四、痛点覆盖对照（切痛点校验）

| 用户痛点 | SPEC 覆盖 | 竞品覆盖 | 判断 |
|---|---|---|---|
| 拼到一半发现缺豆 | ✅ 缺口 + 补货清单（CSV/复制） | AI豆仓✅ 拼豆大王✅ | 打平，底线功能 |
| 家里还剩多少，记不清 | ✅ 盘点 + **估算/精确标记** | 对手有录入无精度概念 | **SPEC 领先** |
| Excel 录入太烦 | ✅ 预填 1000、连续录入、批量整批提交 | AI豆仓批量/套装色 | 打平偏优 |
| 误扣/误触怎么办 | ✅ **撤回任意一条 + 幂等防重** | 均无 | **SPEC 独有** |
| 我想知道用了多少（成就感） | ✅ 已用三指标，口径严谨 | Excel 高频色（半成品） | **SPEC 领先** |
| 低库存提醒 | ✅ 百分比预警（基准不重置） | 拼好豆缺豆提醒 | 打平偏优 |
| 断网/不想注册 | ✅ 全功能离线、无账号 | AI豆仓访客丢数据；拼豆大王云同步付费 | **SPEC 独有** |
| 隐私（截图上传担忧） | ✅ 最小上传 + 删除合同 | 云端处理被横评点名 | **SPEC 独有** |
| **现在库存够拼哪张图？** | ❌ **图纸列表无可拼筛选/标记** | 拼豆大王✅（核心亮点） | **唯一实质缺口** |
| 收纳多盒/多批次 | ❌（首版明确排除，合理） | AI豆仓多豆仓 | 有意识的取舍，可接受 |

**结论：痛点覆盖 9 项领先/打平、1 项缺失。「可拼状态筛选」是竞品已验证、实现成本极低（纯查询计算）、痛点强度极高的功能，建议补进首版图纸列表**（每条图纸显示「可拼/缺 N 色」标记或加筛选开关），与 SPEC 现有「图纸详情逐色缺口」逻辑完全同源，不引入新规则。

## 五、豆计的差异化定位（基于校验结果）

一句话定位：**「拼豆界的记账 App」——比 Excel 快，比 AI豆仓轻，比拼豆大王准。**

竞品都在做「越来越重的工作台」（AI 识别、图纸市集、社区、AR、多端云同步），豆计的反方向壁垒：

1. **轻**：打开就能录，三步记完一次消耗；不强制登录、不强制上传
2. **准**：候选确认制 + 估算标记 + 事务级幂等 + 快照撤回——账永远是可解释的
3. **私有**：数据不出设备，备份用户自己拿着；唯一上传的截图有删除合同
4. **成就**：累计已用/逐色已用/完成数，让消耗记录变成可见的制作成就

## 六、风险与调整建议

1. **【需用户拍板】在线识别的成本位置**：SPEC 把「在线识别 + 删除链路验收」列为关键发布证据（A08/A34，步骤 3）。这意味着选型/部署一个在线 OCR 服务（服务器、密钥管理、删除证据、可能的调用费）——是自用首版**最重的后端投入**。而 SPEC 本身已支持全流程手工录入兜底。建议：**自用安装包的最小交付可以先到步骤 2（记账闭环）+ 步骤 4（分享），把在线识别降级为「增强里程碑」**；若坚持识别为发布阻塞，需接受工期和持续运维成本。这不动任何已确认规则，只动交付顺序。
2. **工程重心提醒**：A18/A25–A29（事务中断、备份一致性、恢复保护）接近金融级正确性要求，是差异化但也是开发量大头。**排期应把最大份额给记账内核与备份恢复，而不是 UI 和分享**。
3. **窗口期**：AI豆仓、拼豆大王均在 2026 年中密集迭代且向「全流程 + 多端 + 会员」演进。它们越重，豆计「轻准私有」的定位越清晰；但拖得越久，用户数据越被锁进对方云端，迁移成本越高。**建议尽快完成最小自用闭环**。
4. **色库维护是长期硬功夫**：MARD 221 社区参考色的准确性、后续品牌扩展（SPEC 已留「按厂商录入」口子）需要持续维护，建议保留 research/ 下的来源核验链。
