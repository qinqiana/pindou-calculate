# 识图训练：学生模型候选清单

调查日期：2026-09-28。对应 Issue #20「识图训练：学生模型候选清单」（父任务 #19，阻塞 #28 学生架构定稿）。本文为资料核验：只用一手来源（官方文档、官方仓库、许可文件、官方包索引），没有安装任何软件包、没有下载模型权重、没有跑 GPU 任务、没有修改主工作区。文中区分「事实（附来源）」「推断」「未核实」。已核实过的体量数据（PP-OCRv6 Tiny ONNX 1.78MB/4.46MB、ML Kit、LFM2.5-VL、GLM-OCR）见 [Jev类模型与端侧识图选型-2026-09-20.md](./Jev类模型与端侧识图选型-2026-09-20.md)，本文不重复。

预算回顾（Issue #20 已确认）：检测器 + 识别器 + 格子分类器三件 INT8 后合计探索目标 ≤ 50MB、硬上限 170MB；许可只接受 Apache-2.0 / MIT / BSD 类，排除 AGPL；能导出 ONNX 或 MNN；训练机 spark-5681 为 aarch64（GB10 / DGX Spark 类），已有 torch 2.13+cu130 与 onnxruntime，没有 Paddle。

## 一、先说训练框架：Paddle 在 aarch64 Spark 上能不能装（事实）

这是全票的前置问题，结论比预期好：

- **Paddle 官方提供 Linux aarch64 的 CPU wheel**，2.6.1 到 3.4.0 全系列都有（`paddlepaddle-*-linux_aarch64.whl`）。[Paddle 官方 cpu 包索引](https://www.paddlepaddle.org.cn/packages/stable/cpu/paddlepaddle/)
- **Paddle 官方提供唯一一个 Linux aarch64 + CUDA 的 GPU wheel：`paddlepaddle_gpu-3.3.1-cp312-cp312-linux_aarch64.whl`，挂在 cu129（CUDA 12.9）索引下**，仅限 Python 3.12。[Paddle 官方 cu129 包索引](https://www.paddlepaddle.org.cn/packages/stable/cu129/paddlepaddle-gpu/)
- cu126 与 cu130 索引下的 paddlepaddle-gpu **只有 linux_x86_64 和 win_amd64，没有 aarch64**；PyPI 上的 paddlepaddle-gpu 最新只到 2.6.2 且全是 x86_64。[cu130 索引](https://www.paddlepaddle.org.cn/packages/stable/cu130/paddlepaddle-gpu/)、[cu126 索引](https://www.paddlepaddle.org.cn/packages/stable/cu126/paddlepaddle-gpu/)、[PyPI paddlepaddle-gpu](https://pypi.org/pypi/paddlepaddle-gpu/2.6.2/json)
- PyPI 上 paddlepaddle（CPU）3.3.1 也只有 x86_64/macOS/Windows；aarch64 CPU wheel 要走 Paddle 自己的索引。[PyPI paddlepaddle 3.3.1](https://pypi.org/pypi/paddlepaddle/3.3.1/json)

**推断：** Spark（aarch64 + CUDA 13 驱动）上装 Paddle 训练的现实路径是 `paddlepaddle-gpu==3.3.1` cu129 aarch64 wheel + Python 3.12 环境；CUDA 12.9 的运行时跑在更新的驱动上一般可行，但这属于 CUDA 兼容性常识，未在本机实测。PaddleOCR 3.x 训练代码与该 wheel 组合的实际可用性同样未实测（见「未核实」）。

**不用 Paddle 的 PyTorch 替代路径（事实）：** 本机已有 torch 2.13+cu130（Issue 背景给定）。MMDetection / MMOCR / MMDeploy 均为 Apache-2.0（[mmdetection LICENSE](https://raw.githubusercontent.com/open-mmlab/mmdetection/main/LICENSE)、[mmocr README license 徽章与 LICENSE](https://github.com/open-mmlab/mmocr/blob/main/LICENSE)、[mmdeploy LICENSE](https://raw.githubusercontent.com/open-mmlab/mmdeploy/main/LICENSE)）；torchvision 为 BSD 3-Clause（[torchvision LICENSE](https://raw.githubusercontent.com/pytorch/vision/main/LICENSE)）。即：检测、识别、分类三件全部可以只用 PyTorch 系框架训练，不装 Paddle。

## 二、许可红线（事实）

- **Ultralytics（YOLO 全系、Ultralytics 版 RT-DETR）是 AGPL-3.0，整系排除。**[ultralytics LICENSE（GNU Affero GPL v3）](https://raw.githubusercontent.com/ultralytics/ultralytics/main/LICENSE)
- RT-DETR 的官方原始实现 lyuwenyu/RT-DETR（Paddle + PyTorch 两版）是 **Apache-2.0**，不受 Ultralytics 影响。[lyuwenyu/RT-DETR LICENSE](https://raw.githubusercontent.com/lyuwenyu/RT-DETR/main/LICENSE)
- PaddleOCR（[README license 徽章 Apache-2.0](https://github.com/PaddlePaddle/PaddleOCR/blob/main/README.md)）、PaddleDetection（[LICENSE](https://raw.githubusercontent.com/PaddlePaddle/PaddleDetection/develop/LICENSE)）、Paddle2ONNX（[LICENSE](https://raw.githubusercontent.com/PaddlePaddle/Paddle2ONNX/develop/LICENSE)）均为 Apache-2.0。
- MNN（阿里端侧推理引擎）为 Apache-2.0；其 MNN-Converter 支持把 ONNX / TorchScript / Caffe / TensorFlow 转成 MNN 模型；Android 核心 so 约 800KB，支持 FP16/INT8 量化（官方称可减模型体积 50%–70%），ARMv8 INT8 为最深优化档。[MNN README（含 License: Apache 2.0、Converter、体积与量化说明）](https://github.com/alibaba/MNN/blob/master/README.md)

## 六、汇总对比与建议组合

体积列：FP32 为官方发布值或官方 state dict；INT8 列为推断（按 FP32 ÷ 4 粗估；MNN 官方称量化可减 50%–70%，[MNN README](https://github.com/alibaba/MNN/blob/master/README.md)）。

| 槽位 | 首选候选 | FP32 | INT8（推断） | 许可 | 训练框架 |
| --- | --- | --- | --- | --- | --- |
| 检测器（通用目标） | PP-PicoDet-S 416 | 1.18M 参数 | 约 1.2MB | Apache-2.0 | Paddle |
| 检测器（文字行，可选叠加） | PP-OCRv6_tiny_det | 1.9MB | 约 0.5–1.8MB | Apache-2.0 | Paddle |
| 识别器 | PP-OCRv6_tiny_rec（或自训小 CRNN） | 4.4MB | 约 1.1MB | Apache-2.0 | Paddle（或 PyTorch 自训） |
| 格子分类器 | MobileNetV3-Small | 9.8MB | 约 2.5MB | BSD 3-Clause | PyTorch |

**推荐组合（推断）：PicoDet-S + PP-OCRv6 tiny det/rec + MobileNetV3-Small，INT8 合计约 5–8MB**，不到 50MB 探索目标的六分之一，许可全部干净。代价是要装 Paddle——而第一节已核实官方存在 cu129 aarch64 wheel（3.3.1/cp312），这条路在 Spark 上有官方轮子可用。tiny det 是否必需取决于 PicoDet 能否直接分出文字区，由实验定（推断）。

**备选组合（推断，全程不装 Paddle）：torchvision SSDLite320-MobileNetV3（INT8 约 3.4MB）+ MMOCR 自训小 CRNN/SVTR-tiny（INT8 推断 1–4MB）+ MobileNetV3-Small（INT8 约 2.5MB），合计约 7–10MB**。训练全落在已有 torch 2.13+cu130 环境，导出走 torch.onnx / MMDeploy → MNNConvert；许可 Apache-2.0 + BSD。代价是识别器没有现成小权重，要自训，且 MMOCR 各模型官方未公布参数量（未核实）。

**不建议（事实+推断）：** Ultralytics 系（AGPL，事实排除）；RT-DETRv2-S（20M 参数、INT8 约 20MB，单件就吃掉近半探索预算，且官方无手机证据，作为检测器对本任务过重）；FasterRCNN-MobileNetV3-320（19.4M，同理偏重）；GLM-OCR / PaddleOCR-VL 等 0.9B 级（前次调查已记，超预算）。

## 七、未核实事项（移交后续票）

1. `paddlepaddle-gpu 3.3.1 cu129 linux_aarch64` wheel 在 spark-5681（CUDA 13 驱动、Python 版本待配）上能否实际 import 并训练；PaddleOCR 3.x 训练脚本与该 wheel 的兼容性。官方 wheel 存在是事实，能跑未实测。
2. MMOCR 的 CRNN / SVTR-tiny / DBNet-R18 精确参数量与权重体积——官方 README 未列，需拉配置或用工具统计（本次不下载权重，故未统计）。
3. ModelScope 读光轻量检测/识别模型的权重体积、Android 端证据——模型卡只给了 iOS demo 线索，API 未返回体积字段。
4. RT-DETRv2 PyTorch 版与本机 torch 2.13 的兼容性（官方 requirements 只列到 torch 2.4）。
5. PP-PicoDet 官方未公布各档权重的 MB 数，本文 MB 为按参数的推断；其 INT8 量化模型在本任务六类目标上的精度需自训后实测。
6. 所有候选在本仓拼豆图纸上的精度、速度、峰值内存——均需训练/蒸馏实验与 Android 真机验证，本文零实测。
7. MNNConvert 对 PicoDet / PP-OCRv6 / SSDLite 具体算子的覆盖率（MNN 官方称支持 158 个 ONNX OP，逐模型未核实）。
8. PP-OCRv5_mobile_det 官方 CPU/GPU 时延是 x86 服务器数据，不能外推到手机（事实边界说明）。
