## What to build

在小程序补货后可查看正确余额、百分比预警和变动原因。

## 实现要点

- 复用新总数补货规则，正向增加与新基准同次提交，减少项指出色号并引导更正。
- 复用逐色基准和用户比例，未知/零基准不做除法，更正及只改标记不重置。
- 库存变动从同一操作记录读取，按操作顺序成组展示，保持原时间和关联。
- 通过微信实际存储验证整批失败保护与刷新，不假设 Android 事务机制在微信直接可用。

## Acceptance criteria

- [ ] B1 10→15 记录 +5；混有减少项整批失败。
- [ ] 1000 基准、10% 比例的 100/101 边界与安卓一致。
- [ ] 历史可解释，重开或网络变化不改数量。
- [ ] 交接实际完成内容、验证方式、结果及未验证边界；技术方案可调整，但不能降低结果要求。
