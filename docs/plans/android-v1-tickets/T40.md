## What to build

用户重新识别或边等边编辑时，能明确选择新候选，旧响应不会抢走自己的修改。

## 实现要点

- 保留识别发起时的图纸、编辑版本和请求身份，返回时与当前上下文核对；过期结果不自动应用。
- 已有手工编辑与新候选冲突时展示可理解的选择，用户明确采用后才更新候选区，旧确认版继续有效。
- 取消、超时、服务失败及再次发起均保留可用输入；线上临时图片清理随每个请求完成，而非只随页面关闭。
- 处理确认之后旧请求返回及恢复备份后旧请求返回，不能跨图纸或跨数据区写入。

## Acceptance criteria

- [ ] 先发请求 A、再发 B，A 后返回不覆盖 B 或用户编辑。
- [ ] 修改数量后重识别，未明确选择采用时原编辑不变。
- [ ] 备份恢复/切图后的旧结果失效，任何失败不改库存。
- [ ] 交接实际完成内容、验证方式、结果及未验证边界；技术方案可调整，但不能降低结果要求。
