## What to build

选择备份后看见新旧数据差异，坏文件被拒绝，取消时原账本完整。

## 实现要点

- 先验证实际文件、容量、格式版本，在隔离区域解析；检查标识唯一性、数据引用、有效色号/数量、流水关系和缩略图解码。
- 只接受明确支持的格式；未来版本、截断内容、重复 ID、断开的关联和容量不足必须清楚拒绝。
- 预览逐色余额/精度差异、图纸和制作/变动数量、缩略图完整性，并明确将整套替换，不合并。
- 到用户明确替换之前保持现有数据不动；取消清理本次准备内容，保留原数据和有效页面引用。

## Acceptance criteria

- [ ] 合法备份显示可解释的差异；取消后余额、图纸、历史逐项未变。
- [ ] 截断文件、重复标识、无效关联和未知新版本均拒绝且原数据可继续使用。
- [ ] 校验不静默纠正坏数量、不截断历史、不先清空现库。
- [ ] 交接实际完成内容、验证方式、结果及未验证边界；技术方案可调整，但不能降低结果要求。
