# T19 — 导出同一时点的完整账本备份

**目标阶段：** 安卓必做  
**负责人：** Android 数据负责人（认领时确定具体人员；主会话集成）  
**状态：** 拆分草稿，待用户批准；不是已发布 Issue 或应用完成记录。  
**验收映射：** 根规格 A25、A29；本票仅承担其中与交付行为对应的部分。

## Parent

[根规格 Issue #1](https://github.com/qinqiana/pindou-calculate/issues/1) 已同步发布根规格 v1.2。实施以该版本的已确认阶段边界为准；历史 v1.0 中的首版 OCR/微信前置条件已由 v1.2 取代。

## What to build

用户主动导出一份包含库存、图纸和全部历史的完整可恢复文件。

## 实现要点

- 按当前版本化业务格式导出色卡来源、余额、精度、预警基准/比例、确认用量与差异确认、制作快照、所有变动、缩略图及必要关联。
- 读取同一一致时点的数据快照；导出期间发生新制作也不能混合前后状态，文件编码不长期占住记账入口。
- 备份直接携带恢复必需的缩略图和色卡资料，排除原始大图、绝对设备路径、凭据与未来付费权益证明。
- 用户选择保存位置，失败或取消不改数据库；说明备份覆盖范围、格式版本、导出时间及不含原始大图。

## Acceptance criteria

- [ ] 准备含补货、更正、两次制作及一次撤回的数据后，导出文件含全部关联和缩略图。
- [ ] 导出过程中发生写操作，备份仍对应一个完整时点。
- [ ] 磁盘满/取消不会报告成功或损坏账本，文件不含密钥和个人配置。
- [ ] 交接实际完成内容、验证方式、结果及未验证边界；技术方案可调整，但不能降低结果要求。

以应用行为、持久数据或本票明确的探索结果验收；不要求为不存在的层新增框架。每票直接交付可演示的完整路径，不单独拆“建表”“做接口”“画页面”作为完成。基础输入校验、错误处理和数据保护随本票实现，不留给最终集成票补救。
