# 点阵计数：路线比较与最小证据

日期：2026-09-16。目的：回答“点阵已明确时，是否可以不逐格读取文字而统计用量”，并为 T28/T38 提供可检查的起点。本记录不是 Android 功能或通用识别通过证明。

## 当前判断

已知每格位置后，可以直接从格内图像统计数量；本项目已经在一张清晰样例上取得实际证据。还须分别解决 **哪些格子需要放豆**、**哪些格子属于同一颜色**、**该颜色对应哪个 MARD 色号**。第一项和第二项不必读取字母数字；第三项需要可靠对照或用户确认，不能由近似屏幕色直接冒充色号真值。

原始 148 颗图的制作格底色规则、空白为棋盘纹理，适合第一轮验证；补充的 47×104 长图有近似色、白色制作格和空白区域、水印，后续须另做人工参考答案和实测，不能推定已经通过。

## 已执行的最小实验

输入为[原始 148 颗 PNG](../../../参考样例/豆画-Mard-148图纸样例.png)，5000×3820。人工提供 29 列 ×16 行的点阵，起点约 (161,315)，格距 5000/31；每色提供一个代表格的色号，另提供两种棋盘背景样本。算法没有读取底部图例数量，没有 OCR、网络、模型或新依赖安装。

步骤：在每格内部取 25 个样点，使用出现最多的 RGB 作为代表背景色；匹配本图人工指定的代表色，累加各色格数。背景样本允许最多 2 个通道值的差异，其他未知色保留为未知，不静默凑数。这是针对已知点阵和本图背景的最小验证，不是最终算法选择。

| 色号 | 本地算法计数 | 既有参考答案 |
| --- | ---: | ---: |
| C2 | 18 | 18 |
| C12 | 3 | 3 |

| C19 | 7 | 7 |
| C29 | 18 | 18 |

共检查 464 格，制作 148 格，空白 316 格，未知 0 格；逐色结果和格数守恒检查通过。

可复现脚本：[grid_probe.py](grid_probe.py)。它接收原始样例文件作为参数，使用本机已有 Pillow 与 Python 标准库；包含逐色参考答案和格数守恒断言。不修改输入图片，不把参考答案作为计数过程输入。

尚未验证：自动点阵定位、自动读取/对应 MARD 色号、其他图片压缩与版式、近似色碰撞、任意遮挡、Android 端性能、Spark 实际部署。人工给定的点阵和色号映射必须随结果披露，不能将这份证据改称“端到端全自动识别成功”。

## 后续本地算法探索

T28 先比较实际输入和结果，不先要求自研整套图像框架。候选手段包括格内背景采样、空白/制作纹理判断、同色归类及用户确认少量映射。只有样例显示现有方法不够时，再采用更合适的现成图像处理能力；例如 OpenCV 已有聚类算法，但是否使用它取决于样例和部署结果。[OpenCV 官方聚类文档](https://docs.opencv.org/4.x/d5/d38/group__core__cluster.html)

颜色标签与物理 RGB 分开：同一图纸内的颜色对照可用于该图的分组验证；官方色值是否取得不影响“统计同类格子”这个实验，但影响自动映射色号的证据。压缩后近似色合并、白色格与空白混淆等必须进入失败样本，不能只增加一个总数校正来遮盖逐色错误。

用户提供的 Spark 可作为开源 OCR 的自管运行候选，实际型号、系统、模型兼容及网络路径仍须到该阶段核验；本轮没有部署或声称它可用。手机请求另一台机器，与手机自身离线计算是两种运行条件，实验和交付记录须写清楚。
