# T21 — 整体恢复备份并保护中断前后的完整数据

**目标阶段：** 安卓必做  
**负责人：** Android 数据负责人（认领时确定具体人员；主会话集成）  
**状态：** 拆分草稿，待用户批准；不是已发布 Issue 或应用完成记录。  
**验收映射：** 根规格 A25、A26、A28、A40；本票仅承担其中与交付行为对应的部分。

## Parent

[根规格 Issue #1](https://github.com/qinqiana/pindou-calculate/issues/1) 已同步发布根规格 v1.2。实施以该版本的已确认阶段边界为准；历史 v1.0 中的首版 OCR/微信前置条件已由 v1.2 取代。

## What to build

明确替换后完整恢复账本，任何阶段失败都能重新打开一套有效数据。

## 实现要点

- 先准备完整的新数据区及缩略图，所有校验和持久化完成后才原子切换；切换成功前持续保留旧数据。
- 恢复保留业务 ID、原时间、原色卡来源、确认版本、制作/撤回关系和请求结果，不把历史变成导入当天的新操作。
- 成功后失效恢复前的旧页面、预估和未完成表单，重新加载当前数据区；旧请求不能写入已替换数据。
- 准备、写入、切换各阶段失败均给出可理解结果；通过明确有效状态选择完整数据，不靠是否存在某个文件猜成功。

## Acceptance criteria

- [ ] 恢复到干净测试区后，逐色余额、标记、基准、图纸、全部历史、缩略图和成就与导出时点一致。
- [ ] 分别中断准备、写入、切换，重开后只能读到完整前态或完整后态。
- [ ] 恢复后提交旧表单被阻止，未知或坏备份不会破坏已有账本。
- [ ] 交接实际完成内容、验证方式、结果及未验证边界；技术方案可调整，但不能降低结果要求。

## 范围与交付证据

不自动合并多个账本，不导入付费权益或 Android 私有数据库作为跨端格式。

以应用行为、持久数据或本票明确的探索结果验收；不要求为不存在的层新增框架。每票直接交付可演示的完整路径，不单独拆“建表”“做接口”“画页面”作为完成。基础输入校验、错误处理和数据保护随本票实现，不留给最终集成票补救。
