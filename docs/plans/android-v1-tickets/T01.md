# T01 — 在 Android 真机安装并保存第一笔库存

**目标阶段：** 安卓必做  
**负责人：** Android 基础负责人（认领时确定具体人员；主会话集成）  
**状态：** 拆分草稿，待用户批准；不是已发布 Issue 或应用完成记录。  
**验收映射：** 根规格 A18、A24、A29；本票仅承担其中与交付行为对应的部分。

## Parent

[根规格 Issue #1](https://github.com/qinqiana/pindou-calculate/issues/1) 已同步发布根规格 v1.2。实施以该版本的已确认阶段边界为准；历史 v1.0 中的首版 OCR/微信前置条件已由 v1.2 取代。

## What to build

安装后无需账号，录入一种拼豆库存，关闭并重开后余额和变动仍在。

## 实现要点

- 沿用已选跨端客户端和 Android 本地事务方案；先打通输入、提交、持久化、重开查询这一条真实路径，工具版本以实际构建结果冻结。
- 首笔写入同时保存余额、精度、变动原因、前后数量、操作标识及成功结果；后续写操作复用这一入口，不做独立通用库存引擎。
- 同一操作的连点和重试复用标识，已成功且内容相同直接返回原结果；内容不同报冲突；新操作在事务内校验所属数据区和当前版本。
- 设置最小源码忽略规则；签名材料、凭据和本机配置不进入仓库或安装包。首次打包前明确签名保管人、稳定应用标识及测试设备。

## Acceptance criteria

- [ ] 真机录入 A1=100，重启仍是 100，可查到对应完整变动。
- [ ] 事务中途异常只留下完整前态；提交成功但界面未回显时重开可查成功结果，重试不重复写。
- [ ] 无账号、广告、支付、OCR 或微信环境也能完成此路径；非法数量拒绝且不改原数据。
- [ ] 交接实际完成内容、验证方式、结果及未验证边界；技术方案可调整，但不能降低结果要求。

## Blocked by

- 无，可以在所属阶段获准后开始。

## 范围与交付证据

不提前实现微信存储、在线服务、全量色卡页面或后续平台框架。

以应用行为、持久数据或本票明确的探索结果验收；不要求为不存在的层新增框架。每票直接交付可演示的完整路径，不单独拆“建表”“做接口”“画页面”作为完成。基础输入校验、错误处理和数据保护随本票实现，不留给最终集成票补救。

**外部条件：** 首次打包前由用户指定签名密钥保管人；实际工具安装按已有授权处理。
