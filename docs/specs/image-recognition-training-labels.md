# 识图训练：标注体系与学生输出定义 v1

对应 [识图训练地图 #19](https://github.com/qinqiana/pindou-calculate/issues/19) 的票 [#24](https://github.com/qinqiana/pindou-calculate/issues/24)。本文定义训练"学生流水线"所用的标注类别、各组件的输出，以及它们如何落到应用现有的候选合同（`app/src/recognition/result.ts` 的 `readRecognition` 输入）。合成数据渲染器、老师标注、评测协议都以此为口径。术语见根目录 `CONTEXT.md`。

用户已裁决（2026-09-28）：杂项四类（标题总数、水印/logo/二维码、行列编号、备注文字）认出但不计数；疑点定位图例按项、格子按格；排版只覆盖现有四类（三类图例排版 + 无图例格内色号）。

## 1. 学生流水线的三件与代码的分工

| 组件 | 输入 | 输出 | 不做的事 |
| --- | --- | --- | --- |
| 检测器（定位） | 整页或分块图 | 下表 9 类目标的框与类别 | 不读字、不数格 |
| 识别器（认字） | 检测出的文字框 / 制作格裁块 | 短文本字符串 + 每字符置信度 | 不判断色号是否合法、不改号 |
| 格子分类器 | 网格内每一格的裁块 | `bead` / `blank` / `unknown` 三选一 | 不读色号（交识别器） |
| 代码（配对与加总） | 上面三件的输出 | 候选合同 | — |

代码负责：网格格距与行列坐标推算（沿用现有确定性逻辑与分块框架）、图例项内 色号↔数量 的配对、色号归一（大写、去前导零、全半角）、MARD 221 校验、重复与共享数量的拒绝、合计与标题总数核对、疑点生成。模型只输出"看到了什么、在哪里、多确定"。

## 2. 检测类别（9 类）

| 类别 | 含义 | 计数？ | 备注 |
| --- | --- | --- | --- |
| `legend_item` | 一条图例项：色块 + 色号 + 数量作为一个整体的外接框 | 是（图例路的计数单位） | 疑点定位的最小单位；三类图例排版都框成"一项一框" |
| `legend_swatch` | 图例项里的色块（可能内含色号） | 否 | 白色/浅色描边色块也要框；用于确认项的存在与"无字色块"排版 |
| `code_text` | 色号文字（C12、H07、M1） | 否 | 只标图例区域内的；格内色号走格子分类 + 识别器，不做检测 |
| `count_text` | 数量文字（(3)、×3、3颗、341） | 否 | 含单位与括号；解析由代码做 |
| `grid_region` | 图纸本体（制作格构成的图案区域）外接框 | 是（本体路的范围） | 不含行列编号、图例、标题 |
| `title_text` | 标题，含"共 148 颗"之类的总数 | 否，只用于核对 | 杂项 |
| `watermark` | 作者水印、logo、二维码 | 否 | 杂项；用于从本体/图例中排除 |
| `axis_label` | 行列编号 | 否 | 杂项；用于从本体中排除 |
| `other_text` | 其他备注文字 | 否 | 杂项 |

框为轴对齐矩形，像素坐标 `[x, y, w, h]`（与合同 `Region` 一致）。同一像素可以同时属于 `legend_item` 与其内部的 `legend_swatch` / `code_text` / `count_text`（父子嵌套）。

## 3. 格子标签

| 标签 | 含义 | 后续 |
| --- | --- | --- |
| `bead` | 制作格：格内明确写有色号 | 裁块交识别器读色号；读出的字符串再由代码校验 |
| `blank` | 空白格：实际未标色号，不放豆 | 不计数；画面颜色不决定是否制作（含白底空格） |
| `unknown` | 看不清、被遮挡、粘连、超出覆盖 | 计入疑点，按格给出位置，不当空白也不计数 |

白色制作格（H2 等）与空白格的区别只在"格内有没有色号"，不看底色。

## 4. 识别器字符集与归一

- 字符集：`A–Z`、`0–9`、`( ) × x 颗 - / :`，共 46 个符号 + 空白（CTC）。中文只保留"颗"，其余单位不进字符集，出现即为 `other_text`。
- 识别器原样输出；代码做归一：大写、去前导零（`C03`→`C3`）、全半角与空白清理。`O/0`、`I/1`、`B/8` 等疑似混淆**不自动改号**，按现有规则生成疑点请用户核对。
- 归一后不在 MARD 221 的色号是"被拒绝识别项"：保留原文与位置，显示"未计入"，不换近似色号。

## 5. 训练标签文件格式

1. **检测**：每图一个 JSON：`{"image": "...", "width": W, "height": H, "objects": [{"cls": "legend_item", "box": [x,y,w,h], "id": "li-3", "parent": null, "text": null}, {"cls": "code_text", "box": [...], "parent": "li-3", "text": "C12"}, ...]}`。`text` 只在 `code_text` / `count_text` / `title_text` 上填写原文。
2. **文字识别**：`{"crop": "...", "text": "C12", "kind": "code" | "count" | "title"}`；裁块由检测框或合成器直接给出。
3. **格子分类**：`{"crop": "...", "label": "bead" | "blank" | "unknown", "code": "H7" | null}`；合成数据的 `unknown` 由遮挡、模糊、裁边等扰动生成。
4. **整图真值（评测用）**：沿用现有参考答案格式 `{"expected": {"C2": 18, ...}, "titleTotal": 148 | null, "status": "complete" | "partial"}`；留出来源组只用这一层比对，不要求框标注。

合成数据三种标签由渲染器同时生成；真图的检测/文字标签由老师（可插拔端点）产出并经人工核对，格子标签首轮只做合成。

## 6. 落到候选合同

学生流水线的最终输出仍是现有 `readRecognition` 接受的结构，不新增字段：

| 合同字段 | 来源 |
| --- | --- |
| `source` | `legend`：至少一条有效图例项；否则 `grid`；两路都不可用则 `failed` |
| `candidates[{code, quantity, evidenceIds}]` | 图例路：`legend_item` 内配对成功且色号合法、数量为整数的项；本体路：`bead` 格按色号累计 |
| `evidence[{id, rawText, region}]` | 每个 `legend_item`（rawText = 色号+数量原文）；本体路每个分块或行 |
| `doubts[{reason, rawText, region, evidenceId}]` | 低置信项、配对歧义、重复色号、被拒绝色号（色卡外）、`unknown` 格（按格 region）、未覆盖区域、标题总数不一致 |
| `titleTotal` | `title_text` 解析出的总数，读不到为 `null` |
| `image.width/height` | 原图像素 |

杂项三类（`watermark` / `axis_label` / `other_text`）只用于排除，不进合同；`title_text` 只贡献 `titleTotal`。

## 7. 老师标注的要求

老师（可插拔端点）对真图输出第 5 节第 1、2 种标签：图例项框、其内文字框与原文、`grid_region`、`title_text`、杂项框。框允许 ±3% 图宽的误差；与旧算法、参考答案三方对账后，分歧项交人工核对。老师读不出或给不出框的项标 `unknown`，不编造。

## 8. 不在本文范围

模型结构与分辨率（学生架构定稿票）、评测通过判定与分项错误统计（评测协议票）、合成器覆盖的变化维度（渲染器原型票）。排版只覆盖现有四类；新排版出现时先登记样例，再决定是否扩类别。
