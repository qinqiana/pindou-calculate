## Problem Statement

用户保存的拼豆图纸存在 PNG、JPG 和 WebP，多数附带逐色数量图例，也可能缺少完整图例。逐项抄录耗时，误读色号、漏读末行或把白色制作格当作空白，会直接影响缺口判断和后续库存扣减。用户需要的是能核对的逐色用量，而不是一串无法解释的总数。

当前应用提供手工确认流程；现有计数实验只在人工给定点阵及每色代表格后，对一张清晰图得到正确结果。仓内现有 18 张图纸（1 PNG、4 JPG、13 WebP）均能看到图例，其中超密大图的图例被截断；另有一张色卡，不能作为图纸计数。全部 13 张 WebP 已核实为单帧 RGB 图像。这批素材能验证多版式图例提取和失败提示，不能直接证明真正无图例场景已覆盖。

本轮一手调研中，公开用户评价同时出现识图省时和识别后仍需大量补改的相反体验，也有图片导入失败、编辑内容丢失和历史记录难区分的个案。因此进一步验证三个问题：能否顺利导入、能否低成本核对正确、确认后的数字和剩余风险能否解释。评价反映当事人报告，不是本项目复现的竞品缺陷或市场发生率；完整性误导和色卡来源风险则由仓内样本、既有业务规则及公开产品能力共同推导。证据与局限见 Further Notes。

## Solution

用户可直接选择 PNG/JPG/WebP 图纸预览、手工录入。2026-09-20 实施补充确认：后续本地识别在用户选图后自动开始，不要求手动框选、填写点阵参数或指定色号；用户可取消或重试。系统从图例和图纸本体自动取得候选并校验完整性，有可靠完整图例时优先采用图例；候选展示逐色数量、来源和疑点，用户可修改并一次确认全部用量。这项确认已纳入本地工作规格，既有规格 Issue 保留其发布版本记录。

识别期间使用原图核对，缩略图只用于保存后的辨认和分享。识别不直接修改库存，旧确认用量和制作快照受到保护。超时、截断、模糊和色号歧义返回明确状态，允许保留已识别部分及独立手工输入。

交付顺序为：①原图输入与样例基准；②图例识别及确认闭环；③无图例本体计数及疑点定位。每一步单独给出实际证据，第二步通过不能代替第三步。

本轮细化以减少最终得到正确用量的总工作量为目标：原图与疑点就地核对、局部修改不丢其他输入、失败给出下一步、知情接受部分结果后持续说明计算范围。市场资料不改变上述算法顺序，也不把功能数量或竞品宣传准确率作为交付目标。

## Implementation Decisions

### 1. 一个识别边界，复用现有确认入口

新增一个“本次图片 → 识别候选”的业务边界，内部容纳解码、区域分析、图例解析与本体计数。候选不持有账本写权限。现有图纸创建、用量确认、缺口计算、制作/撤回和备份恢复入口继续承担各自业务规则。

处理流水线：校验和解码 → 区域及可读性分析 → 图例候选 → 必要时本体候选 → 完整性与冲突检查 → 用户采用和整体确认。分阶段内部函数不作为新的公共服务或独立测试接口；不预建多供应商调度。

### 2. 输入、WebP 与原图使用

- PNG、JPG、WebP 的单幅静态图纸同级支持。WebP 包括有损、无损及透明通道的静态图片；按真实文件内容和完整解码校验，不仅看扩展名或 RIFF 前缀。容量沿用单图 20 MiB、3200 万像素的现有边界，解码前后均检查。
- 使用平台或成熟解码器处理格式，不自行实现 WebP 编解码。应用选图读取用户选中文件的原始字节或可读取的文件引用，选图链路不额外压缩后再识别；无法读取文件时明确报错。
- 先规范显示方向，保留源像素与处理坐标间的变换。颜色、文字和透明信息用于分析；透明像素背后的 RGB 不参与颜色判断，透明本身也不直接证明一个格子为空白。
- 定位可使用降采样预览，文字读取和制作格分析回到原分辨率裁块。放大仅帮助采样和识别，不被记录为恢复了原本不存在的细节。
- 本次会话临时保留原图至核对完成/取消；不新增永久原图存储。离开后重新识别需再次选择原图，作为新图片会话处理；尺寸或文件名相同不能使旧候选自动套用。备份继续不包含原始大图、设备路径。
- WebP 的保存缩略图统一输出 PNG，避免把 WebP 解码依赖传播到分享和备份读取；原图识别完成之前不得用缩略图替换分析输入。转换失败应返回明确错误并保留前态。
- 多帧动画不属于单幅图纸计数输入，明确提示不支持，不能静默取首帧或合并帧。本轮素材均为单帧；动画选帧体验另行提出需求。

这里的原图指用户本次选中文件的原始字节，不要求证明它是作者首发版本。已被社交平台压缩过的截图仍是有效输入，系统避免再次无必要降质，按可读性返回候选或疑点；不能因无法取得“更早的原图”直接拒绝合法截图。无图例图和图例被截断图也不因没有底部数字而拒绝导入或手工录入。

### 3. 区域识别与路由

定位标题、制作区域、坐标轴、逐色数量图例和明显遮挡，输出能还原到原图的位置。图例可由色号文字、数量配对和色块布局共同定位，不固定截取图片底部某个百分比，不要求固定作者模板。颜色只能帮助找区域和归类。

优先产生图例候选，保留完整性证据。只有图例范围完整、每个可见项目有可解释的处理状态、配对可靠且没有未解决冲突时，才标为“已取得待核对候选”；有可用数据但缺失或歧义时标为“部分识别”。找不到完整图例时尝试本体计数；两路都无可靠结果则失败并保留手工入口。

完整性采用可见版面边界、未配对项、被截断色块/文字、实际覆盖区域和可读的色数/总数交叉检查。标题和图例总数相等只是辅助证据，不能单独证明完整；不可读的标题和色数保持未知。制作区域存在未能覆盖的边界时，即便已计数区域内部格数守恒也不能报完整。

两路结果分别保留来源。同一用量不能将图例数量与格子计数直接相加；完整且可靠的一路可以成为采用候选，另一条存在冲突时必须展示冲突并降为待核对的部分结果。不得依据标题差额补数字或把本体计数强行调成图例答案。

### 4. 图例文字读取与配对

按 2026-09-20 的轻量实施方向，先以现有图像处理能力和小型通用字形模板建立可复现基线，固定实际版本及有效参数，不安装通用 OCR 引擎。字形模板属于字符识别，不能改称完全不读文字；字体、模糊、断笔等不支持情况明确拒绝。PaddleOCR 等小型识字工具保留为实际需要时的比较候选，接入与新增安装另遵循既有授权，不以模型名称决定路线。

依据文字框、色块和行列关系处理三种已观察排版：色号与括号数量同条；色号色块右侧紧邻数字；色号位于色块内、数量位于其下方。支持换行、末行稀疏项、白色无边框色块和混合字号。空间配对先于整行字符串顺序；一个数字若可对应多个色号则保留歧义，不强制配对。

只对安全形式做归一：大小写、全角半角和间隔。O/0、I/1、B/8 等混淆保留原文及可能解释，不能为了命中色卡而自动改号。色号须通过 MARD 221 集合校验；每色数量沿用 0–10 亿的现有非负整数边界，最终用量每色仅一项。逐色合计独立验证为可精确表示的非负安全整数，不把单色 10 亿上限误作总量上限。221 色各自合法时总量至多 2210 亿，仍可精确表示；新识别入口不能靠截断或取近似值修复坏数量。数字被遮挡不能按前半段解析，漏读不能记零。

同一文字框在重叠裁块中重复检测可按源位置去重；不同图例位置的同号项目必须分别保留为重复候选，不累加、不取最大值。低置信文字不能仅因引擎阈值过滤而消失：保留原始候选或将可见但未解读区域标为疑点。置信分数表示引擎打分，不称为正确概率。

合法编号不单独证明色卡来源。存在明确的非 MARD 标记、多个品牌对应栏或色卡版本冲突时，保留标记原文及位置，提示当前仅按 MARD 221 处理；不能因为另一栏的编号恰好合法就自动选入。无来源标记的常规图纸不增加每次必填品牌步骤，也不声称已验证为官方 MARD；按当前色号集合生成待核对候选。色卡外项目沿用知情继续规则，不自动换为近似色或另一个品牌编号。

### 5. 图纸本体计数

本体识别首先验证规则点阵图纸。网格线不是强制公共接口；实现先复用 OpenCV 的横纵线提取，加局部周期/文字中心分布交叉核验制作区域。分别估计横纵格距和起点，校验粗线、虚线及 5/10 格分隔造成的倍数误判。行列标号可辅助验证，不作为制作格，也不凭截图像素尺寸编造行列数。

在已覆盖区域内，每个位置仅属于“确认制作格、确认空白格、未知格”之一。制作格的色号再分为已知、歧义或色卡外项目。记录这些计数与覆盖范围，未定位区域独立标记，不能纳入假定空白。

格内分析避开网格边缘，对文字区和底色区分别取特征。底色使用多点/小区域的稳健统计，同图聚类允许压缩造成的色差；不再依赖精确 RGB 相等，也不将社区色卡最近色当作色号依据。

文字识别为色号的直接证据；清晰格可建立本图内部的底色—色号对照。只有多处高可信文字与色组一致、没有跨色号碰撞时，才将该映射用于同图其他清晰制作格。一个色组对应多个色号时拆分复查或保留歧义，不传播多数色号。仅人工指定代表格时，整次结果明确记为人工辅助。

“高可信”、颜色距离、定位残差及色组一致性的阈值属于所选引擎的有效参数：只使用预先划定的开发样例校准，记录数值及其拒绝条件，冻结后在验收组验证。不能仅凭 OCR 分数高或同色多数一致传播色号；必须同时通过制作格判别、位置覆盖和色组无冲突检查。参数调整后重新报告受影响组，不用改验收集合来提高通过率。

白色制作格与无字空白格依赖格内文字/纹理等证据区分。没有识别到文字不等于确认空白，水印也不能当作制作文字。遮挡、文字和底色冲突、采样不稳定均保持未知；不得靠邻格、对称图案或数量差额猜补。

长图分块保留原图坐标和有效区域，用位置唯一归属去重；处理区域覆盖相邻块边界，已处理块不会因重试重复累计。部分块失败时保留已取得部分和失败区域，不输出假完整。

本体基准必须隔离图例数量：用于该路线的输入不包含图例/标题总数；参考答案仅在结果产生后比较。无图例测试不能使用图例色块生成色号映射。自动定位或自动色号不足时，可以验证少量人工校准的辅助路径，但不能用该成绩通过全自动验收。

### 6. 候选合同与来源

候选合同与应用版本、备份版本分开管理，第一版包含以下业务内容；具体序列化和平台封装由实施保持这一语义。

| 内容 | 约束 |
| --- | --- |
| 任务身份 | 请求标识、图片会话标识、图纸标识、发起时编辑修订、数据集世代；不采用文件内容指纹 |
| 图片信息 | 实际格式、原始像素尺寸、方向和坐标变换；无设备绝对路径 |
| 原始证据 | 原始文字/数量、源区域、所属路线及引擎/解析版本；没有置信分数则为空 |
| 有效候选 | 合法色号、数量、证据引用；尚未成为确认用量 |
| 疑点与拒绝项 | 稳定的本结果内项目标识、原始内容、原因、区域、未计入或可能漏计的说明 |
| 完整性 | 已取得待核对候选/部分识别/失败；覆盖说明、未知格/区域、截断和冲突原因 |
| 核对信息 | 标题总数、可读色数、候选合计及差异；未知与零严格区分 |
| 人工参与 | 原始自动结果、是否人工校准/映射，以及用户采用和修改后的结果分别记录 |

若只知道未知区域而无法数出未知格，不伪造格数；保留区域和“数量未知”。被拒绝项始终不进入有效候选合计。

识别完整性与用量确认状态是两个独立事实：整体确认表示用户采用这一版数字，不会抹掉该版的原始识别疑点或把引擎结果改为全自动成功。保存原始状态、用户已解决的疑点与仍知情保留的风险摘要；修正一个数量不自动证明其他未覆盖区域完整。独立手工录入的完整用量沿用手工来源，不反推自动识别成绩；由自动候选修改而来的用量仍保留候选来源及人工修改事实。

### 7. 采用、确认与异步保护

发起识别时固定图片会话和编辑修订。取消、换图、新请求、离开会话或恢复备份后使旧任务失效。返回时检查任务身份与当前编辑；任何不匹配均不得自动填入输入框。主动采用候选之前展示其与当前输入的差异，保留取消路径；已有编辑由用户明确选择采用后才能替换。

编辑修订是图纸编辑会话内的递增编号，修改色号、数量、标题总数、采用候选或调整识别范围时递增；另记录发起时图纸确认版次和数据集世代。不得用全局账本操作序号代替，也不计算草稿或图片哈希。浏览、缩放和同一会话内无关库存写入本身不使识别结果过期；切换页面导致原会话结束、恢复数据集或同图纸确认版次改变则失效。最终用量提交仍使用现有账本并发保护和最新有效 token，不能为了接收识别结果绕过持久化校验。

用量确认仍通过现有主按钮一次保存。部分识别、拒绝项、重复候选和总数差异的风险先明确展示并记录用户知情确认；这些确认绑定实际被采用的候选和当前编辑修订，修改后不能复用旧确认。重复/歧义项目先由用户修正或明确保留为未计入项，合法逐色用量通过原校验后整体提交。

结果为空且识别失败时不能自动生成零用量确认；用户仍可独立手工录入零用量并按现有规则确认、已拼。识别、候选采用和用量确认都不触发库存扣减。

#### 手机核对与失败后的下一步

核对页持续提供原图放大和候选列表；每个疑点显示原始内容、当前解释、问题原因及对应区域。未知区域无法命名色号时按区域显示，不能只列出已识别色号而使漏项无处可查。允许先查看疑点再查看全部合法项，仍是一次整体确认，不新增逐色勾选任务。

打开原图放大、疑点详情、键盘或在原页面切换查看内容，不结束当前编辑会话；这些查看行为与真正离开/换图区分。修改一项保留其他输入和查看位置。无效数字在对应输入处说明原因，整体保存前重新校验；错误不导致整份候选清空。具体布局由视觉稿验证，不在规格固化新页面数量。

| 失败/疑点 | 保留内容与下一步 |
| --- | --- |
| 文字小、遮挡、压缩或图例被截断 | 保留可用项和源区域，说明缺失内容；可选更清晰文件或在当前图上手工补充，不循环重试同一输入来假装会恢复细节 |
| 格距/制作区域不可靠 | 保留未覆盖区域，提供手工用量；只有实验证明有效时再提供局部校准 |
| 未发现可用图例 | 说明正在尝试本体或本体暂不可用；用户随时可继续手工，不误报图片格式不支持 |
| 网络/服务/超时 | 保留当前图和编辑，可取消、重试同一图片或手工；服务端按原删除规则清理 |
| 已有编辑与新候选冲突 | 展示可选择的新候选，默认保留当前输入，不静默覆盖 |

进入图纸详情、缺口查看以及生成补货清单时，若当前确认版仍有知情保留的部分识别/拒绝项/未知区域，持续展示“按已确认用量计算，仍可能漏计”的范围说明。已有公式、已拼入口、库存不足检查和知情继续权限不变；不得只显示没有限定的“整图足量”或把风险状态当作新增扣减禁令。补货清单沿用现有数据列，生成前页面说明范围，不在本轮改变导出公共格式。分享视觉内容仍遵循根规格，不顺带增加新卡片字段。

### 8. 数据与备份兼容

现有用量只允许手工来源。后续扩展必须同时覆盖用量类型、确认写入、持久化读取、备份导出/恢复及显示；来源至少区分手工、图例识别、本体识别、人工辅助。保存采用来源、算法版本、自动/修改后结果摘要、完整性及相关知情确认，不能把自动候选一律记为手工。

未确认候选和原图仅属本次会话，未采用的候选不进入正式用量。确认后的来源及知情确认属于业务数据，进入一致快照和备份；不持久保存无关整页 OCR 文字、原始图片或全量逐格调试信息。

确认结果增加这些语义时将完整备份格式升到第 2 版；新版本读取第 1 版并将旧记录按真实的手工来源迁移，保持 ID、时间、用量、缩略图、流水和制作快照。第 2 版往返保留新增来源与知情确认。旧应用读取第 2 版应明确拒绝并保持原数据，新应用拒绝未知未来版和损坏数据，不静默降级或清库。只增加 WebP 输入且仍存 PNG 缩略图的阶段不单独升级备份格式。

第 2 版的触发点明确为首次持久化非手工确认来源及其必要的来源/风险确认记录，而非更换图片格式。现有第 1 版读取校验只接受手工来源，因而仅扩展来源字符串枚举也不与旧读取器兼容；不能以“只加了枚举值”为由继续导出第 1 版。纯展示性的可忽略扩展不在本次新增数据范围内。迁移必须先校验旧记录，无法证明为合法旧格式的数据拒绝处理，不凭缺失字段推定可迁移。

当前确认版的剩余风险摘要应在重开和备份恢复后保持，以便缺口页继续说明计算边界。旧手工记录没有这份自动识别证据时保持“手工来源/未提供自动证据”，不能编造已完整识别或未解决识别问题。查看旧制作记录时，来源与风险依其用量版次关联，不从图纸最新版本反推。

### 9. 运行位置、性能与服务边界

先在本地实验进程完成真实图片基线，记录设备、运行环境、引擎版本、耗时及峰值内存；不以 Python 能运行推定 Android 可运行。通过后对同一最小样例做 Android 原图解码、候选返回、放大核对和确认的真实闭环，才决定最终运行位置。

优先验证本地能力；若必须接入 Spark/外部 OCR，则提交具体部署、费用和截图留存方案并取得相应授权。手机调用 Spark 属于联网识别，不称为手机离线计算。在线路线只接收主动选择的图片，不发送账本；成功、错误、超时和取消都须完成已确认的删除要求。

耗时处理不阻塞编辑和取消，分块间可终止；超过 30 秒仍未完成时提供重试或手工路径，结果迟到也不得覆盖编辑。记录长图及大原图的实际内存和耗时，不提前承诺识别准确率或手机速度。引擎不合适时在同一候选合同下调整实现，不为维护原路线降低验收。

## Testing Decisions

### 1. 最少的外部行为测试入口

算法只测“输入图片 → 候选及疑点”的完整边界；应用沿用“导入 → 采用/修正 → 整体确认 → 重开/备份恢复”的现有操作入口。只在取消、迟到响应和持久化失败等必要场景控制任务完成时机，不以伪造 OCR 结果通过算法验收。

既有先例包括 148 颗逐色断言、缩略图生成与分享读取、用量确认/制作快照、旧数据读取失败保护、备份往返测试。保留这些行为，新增与格式、识别来源和异步路径相关的最小检查，不为每个图像内部步骤各建一套测试。

### 2. 样例基准与证据隔离

- 在调参之前登记全部 18 张图纸和 1 张非图纸色卡，标明原文件、版式、来源组、格式、是否完整、是否有可核对答案。缺少答案不按零处理。相同作者模板/同源近似版本成组，预先冻结一部分整组仅验收；不能在看到失败后将其移出统计。
- 图例参考答案由人工逐项抄录复核；标题和打印图例出现矛盾时记录矛盾，不把标题当真值。本体参考答案须人工逐格核对，不能只复制图例数量。
- 当前图纸均有图例。保留原图，另建立隐藏图例的派生测试输入，记录裁切范围；原图与其变体保持在同一数据组。另补真正无图例的真实图纸，派生图不能替代这一证据。
- 首轮至少覆盖三种图例版式，以及白色/空白、近似灰色、JPEG/WebP 压缩、长图、末行稀疏项、水印和截断。声明支持的清晰样例须逐色逐数全对；边界样例须给出可定位的部分结果或失败，不以平均分掩盖错误。
- 记录每张自动结果、人工输入、最终修正、错号/错数/漏项/多项、未知区域、整图完全正确与否、耗时和内存。报告全量分母、通过数和失败原因；不得只展示成功图。
- 148 颗本地采样基线已在本次调查复现：人工点阵及代表色号下，九色一致、148 制作格、316 空白、0 未知。现有报告引用的批量探测命令不在当前脚本中，旧跨图结论不可替代新的可复现记录。

2026-09-20 后续实施确认：原 18 张是基础开发回归，最低 15/18；每色允许误差 `max(真值×10%,3颗)`，不允许错号、漏色、多色或重复合并。无完整独立参考答案的图留在分母、不计通过。该容差适用于本轮本地候选算法；完整性状态、自动结果与人工修正、账本精确计算仍分别验收。基础完成后先冻结源码/参数/字形资源，按用户要求由 Luna max 收集 30 张新来源图紙，主会话核对真值并验证冻结版；新样本的首次结果与后续调参回归分开，先正确再精简。

### 4. 省时效果与真实核对成本

正确性先按 R01–R22 检查，再比较是否减少用户工作。选择覆盖三种图例版式和白色/长图边界的已核对样例，分别测现有手工录入与识别后核对两条路径；记录操作者、设备、图片、先后顺序和熟悉程度，避免重复同图记住答案后将学习收益算作算法收益。

计时从选中图片到保存可用确认用量，包含处理等待、原图查看、修改、漏项补录和失败后转手工；另外单列用户主动操作时间、修正项数、未发现错误数、放弃/失败数。原始自动正确、人工纠正后正确和仍知情保留风险分别计数。失败样例进入分母，不只对自动成功图计算平均值。

不预设“99%”“几秒完成”或固定节省比例。报告样例分布、逐图记录和中位耗时，只有在相同正确性要求下核对总负担确实下降，才称该路线有省时证据；若用户漏掉算法错误或改错比手工更费时，应调整疑点提示/支持范围并报告结果。小规模自用验收只支持这些样例和操作者的结论，不外推市场平均收益或付费意愿。测量采用本地验收记录，不新增后台遥测或用户行为上传。

以上为验收要求，当前仅已知人工点阵下的 148 基线具有本次实跑证据。算法结果、平台能力、独立文档审核和用户体验验收分别报告。
