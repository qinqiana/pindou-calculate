# #7 / #8 / #9：大图读取、底栏与批量录入返修

日期：2026-09-23。目标应用版本仍为 0.2.0。接续 [上次交接](../../handoffs/issues789-20260922-stop.md)，本轮处理已确认闭环内的大图读取卡顿和界面问题，不修改账本或备份格式，也不改变导入后自动识别。

## 已复现与修复

- 系统选图逐块读取时，`ByteBuffer.array()` 把 65536 个字节逐项穿过 Native.js，再传回 Java 编码。一块真机实测 2122ms，3000021 字节原图需 46 块。改为原生通道直接写入 Android 自带的 [Base64 编码流](https://developer.android.com/reference/android/util/Base64OutputStream)，读完只将编码字符串传回 JS，仍在读取过程中执行 20MiB 上限检查。原图完整字节保持不变，没有压缩后用于识别。
- 上次固定底栏使用写死的页面底部留白。用量页出现标题差异后，底栏顶部在 594px，最后输入框底部在 631px，滚到最底部仍遮挡约 37px。本轮让内容区滚动、操作区按实际高度占位，同样处理批量录入与图纸详情。标题差异仅保留一个明确的确认按钮。
- 批量页面点预览后，221 项预览的首行仍在 2728px 以下，813px 高的视窗内看不到，但保存按钮已可用。本轮预览完成后自动滚到预览。保留用户已要求的全选、分组选择、统一填数和底部保存。
- 只改估算标记原来只显示 `1000 → 1000`，现在同时显示 `估算 → 精确`；数量和标记均未变化时说明无需保存。
