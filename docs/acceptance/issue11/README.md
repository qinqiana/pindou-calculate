# Issue #11：异常图例的纠错与知情确认

2026-09-23，应用 0.2.0，算法 `pixel-glyph-0.10.0-dev`，当前备份 v2。继续交付到 [PR #16](https://github.com/qinqiana/pindou-calculate/pull/16)，本轮以 #11 收尾图例核对这条开发线；#12、#13 和 #14 仍分别承担无图例计数、长图/密集图及综合验收。

## 本次实现

- 疑点可直接补录用量，新行保留对应原文和原图位置。其他行与位置不变；查看/缩放不结束编辑。重复色号在输入行直接指出，正式用量仍每色一项。
- 修改色号、数量、标题或补删条目后，先前的“已修正”和风险接受失效，用户须按当前内容重新核对；整体确认不等于完整识别。确认版继续保存自动候选、人工修改、已处理疑点和剩余风险。
- 复用现有字形模型检查明确的拉丁色卡标记。发现来源冲突时，数量全部留作未计入证据；不因编号恰在 MARD 221 内就采用，也不自动跨品牌换色。无标记的常规图纸不增加品牌必填步骤，界面明确没有认证图片品牌或官方色值。
- 对有原文证据但没有可用候选的结果，提供“保留疑点，手工补录”。当前来源记录允许 `originalStatus: failed`、空原始候选及 `source: assisted`，如实保留失败与后续人工参与；不把手工补录改记为自动成功。当前备份往返保留这些事实，没有新增旧开发版兼容层。
- 每色仍最多 10 亿。候选合计独立校验为安全整数；标题总数的录入、确认、来源和备份校验统一使用安全整数边界，两色各 6 亿并填写 12 亿标题可以正常保存、重开和恢复。
- 详情分行展示原始状态、疑点原文及处理结果，持续显示计算范围；补货前沿用范围提示，CSV 四列不变。确认不扣库存，不追改旧制作快照，独立手工零用量仍可确认和已拼。

## 修复与边界

新增来源检查的首轮 S01 手机运行触发 30 秒保护，未采用或保存空结果。检查复用了不完整的旧网格结果，重复扫描了已由版式分析定位的制作区域；改为复用该区域和已有字形模型后，S01 在原时限内完成。没有放宽超时。此前尝试加严字形语法造成 S01/S13 漏项，已撤销该尝试，保留原字形推理和数字边界校验；最终 26 项严格回归无退步。

来源标记检查当前覆盖清晰、位于已定位制作区域和用量字段之外的 MARD、ARTKAL、HAMA、PERLER、NABBI 拉丁标记及邻接色卡数字；最多检查 80 个外部文字块。不宣称能识别任意中文品牌、商标图案、模糊字样或所有色卡版本。没有检测到冲突不表示已认证 MARD，更不表示官方色值。品牌样例是明确记录的派生输入，不算新的独立泛化样本。

用户原账本只读，测试及恢复产品界面前后按原文本直接比较，未计算哈希。测试桥与隔离配置仅在 `/tmp` 副本，不进入产品构建。当前没有可确认符合用户模型级别限制的独立 QA 模型：**自行复核，未做独立 QA**。本轮未合并 PR、未公开发行或制作正式签名 APK；用户体验与审美验收未代为完成。
