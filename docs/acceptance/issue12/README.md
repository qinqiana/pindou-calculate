# Issue #12：无数量图例的本体计数与核对

2026-09-23，继续交付到 [PR #16](https://github.com/qinqiana/pindou-calculate/pull/16)。应用 0.2.0、算法 `pixel-glyph-0.11.0-dev`、当前备份 v2。

## 实现与范围

- 复用已有逐格读取。无完整数量图例时，某一格读不清不会再丢弃其他可用用量；制作格按位置累计，同一色号在不同格正常累加。已验证编号边框内部的行列号不再误作外部图例、阻断本体后备。
- 本体的每色候选可以查看原图代表格。未知格按行列保留原文及定位区域；已读、空白、未知及未证明外围覆盖分别说明，不把未知补成零或白色。不新增人工框网格、代表色映射或校准步骤。
- 沿用图例优先及既有完整本体后备规则。独立完整本体与采用图例数量不同，显示两路数值及各自原图位置，状态降为部分，不相加，不按标题差额改数。差异文字进入现有风险记录，重开及备份后仍保留。
- 详情可展开原始自动用量，对照当前已确认用量。人工修改保留原本来源及 `modified`，不抹掉原始状态和风险。复用现有确认、备份和制作快照，没有新增账本、依赖或旧开发版兼容层。

本轮证明的是**清晰、规则、有格内色号的小图取得准确可核对候选**。不承诺任意字体、水印、模糊图或长图完整识别；#13 和 #14 不并入本次范围。已有大图实验能力和保护上限保留，没有扩大其已验证范围。

## 样例、真值与冻结

[清单](../../../experiments/issue12/samples.json) 记录输入、原站链接、作者、格式转换、来源组和裁切坐标；[逐格参考](../../../experiments/issue12/references.json) 保留四张小图每一行的色号和空白。

- M040、M060、M023、M024 是此前采集的 BitBead 公开原生制作图；原 SVG 本身没有数量表，仅用已安装渲染器栅格化，不删除图例、不依据网页答案重画。四张同属一个站点模板，全组作为本轮冻结后回归。它们曾用于旧算法，不称为新盲测、四种版式或市场泛化成绩。
- 主会话在本轮执行前逐格目视核对 PNG 和原生 SVG 位置文字，并由独立参考统计累计。逐格参考不是识别器输出；此处也不声称有独立人工 QA。识别子进程只拿图片路径，输出后父进程才打开参考文件。
- 豆画 148 图及变体同属开发组。裁切 `[0,150,5000,3057]`，去掉标题和全部数量表；保留原图作对照。遮坏白色格的变体是失败保护测试，不计为真实无图例新样本。
- 两张同源爱心同属水印边界组，裁切 `[0,0,1080,1083]`；与既有完整图例比较，未完成新的逐格真值，不能据其参考表宣称本体已通过。

本轮没有调字符模型或颜色、定位、传播阈值。沿用模板误差上限 0.36、间隔 0.04、文字对比 65、2000 像素定位预览；备用逐格读取分数须大于 0.6、文字中心偏差不超过格距 0.2。普通读取区为格宽 0.88、格高 0.72，必要时检查重叠区并拒绝文字裁断。空白仍使用原有纹理判断；参数和模型在四张小图运行前固定。

当前逐格路线直接读格内文字，只复用完全相同像素的识别结果，不通过社区 RGB 最近色、同色多数投票或图例色块传播色号。模型分数不是正确概率。带四边连续编号的原有完整性验证上限 4096 格，备用实验读取原有 40000 格上限未改；后者不因此获得手机大图验收。

## 主机结果

[完整逐图结果](body.csv) 保留全部七张输入：**四张真实无数量表图 4/4 逐色逐数一致；148 派生图 1/1；两张水印边界图均未逐色全对**。没有把 5/7 写成七张均通过。

| 输入 | 自动颗数 | 关键检查 | 状态 |
| --- | ---: | --- | --- |
| M040 | 133 | 5 色、同号在不同位置累计 | 部分，逐色全对 |
| M060 | 116 | H2 白色制作格 32，未把外围空白计入 | 部分，逐色全对 |
| M023 | 127 | H2=7、H5=74、H7=32 等 6 色分别正确 | 部分，逐色全对 |
| M024 | 168 | F21=4、F24=46 等近色没有合并 | 部分，逐色全对 |
| 148 裁切图 | 148 | 9 色全对，316 空白、0 未知 | 待核对候选 |
| 同源爱心 S11 | 884 | H2=6；其他色仍有错漏 | 部分，不通过准确计数 |
| 同源爱心 S12 | 890 | H2=328，图例为 339；另有错号 | 部分，不通过准确计数 |

四张真实小图的外围完整性尚未证明，一些带细边线的空白格被保守列为未知。虽然逐色数量全对，仍保留部分状态和风险；不能把这些未知格称为确实漏掉的豆子。此保守处理会增加核对工作量，本轮未测得省时收益。

原 148 图的一个 H2 格改印 Z99 后，独立本体自动得到 147，H2=13、316 空白、1 未知；Z99 可定位且未计入。未用原图图例或颜色猜回 H2。图例 H7 改印 61、本体仍为 60 的像素派生图保留 149 颗图例候选和两个冲突位置，没有将两路数量相加或强改成 148；它是派生冲突测试，不冒充自然采集的新冲突图。

应用测试 **98 项**、算法检查 **28 项**通过，最终 Android 资源构建成功。[图例回归](legend-regression.csv) 中 26 个完整参考输入仍逐色全对，截断 S03 仍为部分且不算整图通过；[#11 七项异常回归](negative.csv) 均符合保护预期。测试未安装或升级依赖；受沙箱限制的应用子进程/本地通信检查改在现有主机环境完成。

Linux 每图新进程：四张小图识别约 0.107–0.153 秒，进程峰值 RSS 73.98–76.53 MiB；148 派生图 1.277 秒、181.01 MiB。它们不是手机内存或用户操作时间。

## Android 实际闭环

Xiaomi 14 Ultra / Android 15，官方开发调试基座，隔离账本 `pindou.acceptance.issue12.20260923`。由 Android 文件 API 读取随隔离资源带入的 PNG 原文件，进入实际本地 Pyodide worker、核对页面和确认入口。没有通过模拟识别结果取得这些数值；本轮未重复系统选图器和备份选择器，相关已有证据见 #7–#9。

| 输入 | 自动结果及确认 | 算法耗时 |
| --- | --- | ---: |
| M040 | 133，5 色全对，知情保留部分风险 | 0.743 秒 |
| M060 | 116，5 色全对 | 0.783 秒 |
| M023 | 127，6 色全对 | 1.125 秒 |
| M024 | 168，6 色全对 | 1.468 秒 |

[逐图记录](android-cases.json) 区分原始候选和最终用量；[两路冲突记录](android-conflict.json) 保留实际冲突和位置。四张小图从测试脚本开始导入到候选返回约 6.3–9.0 秒，148 两个输入约 18.1–20.3 秒，包含图片准备、页面切换、运行时准备及测量开销；不是人工核对耗时，不据此宣传省时。

[内存采样](android-memory.json) 记录 `dumpsys meminfo io.dcloud.HBuilder` 主进程 PSS，观测范围约 204.5–258.3 MiB。只覆盖该进程与采样时刻，不是所有 WebView/worker 进程的合计，也不声称测得整个应用的绝对峰值。

在未知格图先制作一次，再采用本体候选并改数：确认前后库存及旧制作快照相等。确认保存后重启应用、恢复本次导出的当前 v2 备份，图纸、原始用量、人工修改、风险、库存及制作记录逐字段一致，最后增加的两路冲突记录也完成往返。[持久化证据](android-persistence.json)。测试期间及恢复产品界面后，用户原账本按原文本比较保持不变，未计算哈希。

主会话亲自检查[未知格定位](unknown-position.png)与[原始用量展开](detail.png)：标记对应第 5 行第 23 列，放大不丢输入；原始自动用量与当前用量的说明清楚，详情仍可滚动查看风险及缺口。测试桥和隔离配置只在 `/tmp` 副本，不进入产品资源。

**自行复核，未做独立 QA**：当前没有可确认符合用户模型身份/级别边界的 QA 模型。未合并 PR、未制作正式签名 APK，未代替用户完成整体体验或审美验收。
